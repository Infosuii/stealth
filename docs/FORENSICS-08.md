# Model-class capability versus selection failure

Registered after repairs07 failed its temporal guard. A matched raw-input rescue improved late latent-tree
FIT, but rerunning nested selection chose a worse complete model. Do not reject the model class or assume
the repair works globally. Separate capability from whether the existing validation objective ranks candidates
usefully for the next period.

Refit every completed, already-registered trial from campaign03, representations04 and repairs07, using its
own stored parameters and original median inner count on its original outer training partition. No new
parameter search, count choice, data change or target period. Score only the same historical discovery
windows below 5300. Reconstruct each original selected ensemble and require cached-prediction parity.
Read source SQLite files in read-only mode and retain their hashes.

Report, per family/window: descriptive correlation between inner objective and later FIT, the distribution
of individual later scores, where the actually selected members fall in that distribution, and whether good
candidate models existed but were not selected. The maximum later score is an unavailable oracle diagnostic,
not a deployable winner. Trial scores share data and are not independent samples; do not attach a naive
across-trial significance test. Do not choose or promote a model using its later diagnostic score.

Preserve all outcomes and distinguish search/selection failure from a model class whose whole trial population
underperforms. Any selection-policy repair needs its own frozen algorithm and chronological gates. No
confirmation/audit labels, old-cache writes, platform actions, uploads, submissions or staking.
