## 1. Scoring — exact formula (from GET /api/v1/scoring = eiq_explain_scoring, and SDK `everestapi.scoring` source)
- `payout = stake * score`, `score = b * arctan((FIT + UNQ + INOV) / b)`, `b = 0.6366197723675814` (= 2/π). Weights fit=unq=inov=1. Max |score| per round = b·π/2 = **1.0**, i.e. a single round can win or lose the entire stake. The SDK states "There is no payout factor, clip or stake-return squash" for the tournament.
- All three terms are **covariances with the mean-centred target, computed per exped (cross-section)**. A live round = ONE exped = **90 instruments** (universe_size 90). So each round's score is a covariance over 90 points: very noisy; Sharpe over rounds is what separates models.
- **FIT** (`fit20`): `r = (rank_avg(p) - 0.5)/n`, clip to [0.001, 0.999], `z = norm.ppf(r)`; `FIT = mean((z - mean z) * (t - mean t))`. Only ranks of predictions matter; no power transform; not divided by target std. Empirically on train: FIT ≈ **0.226 × Spearman** (target std 0.225). So FIT 0.02 ≈ Spearman 0.09; FIT 0.04 ≈ Spearman 0.18.
- **UNQ** (`unq20`): gaussianize preds `p` and benchmark `m` the same way; `ortho = p - m * (m·p)/(m·m)`; `UNQ = mean(t_c * ortho)`. **Zero rule:** if the benchmark's own covariance with the target on that exped is negative, UNQ = 0 for the exped. Algebra: when benchmark is positive, `UNQ = FIT − β·FIT_bench` with `β = (m·p)/(m·m)` (≈ rank correlation with benchmark). Needs ≥5 common rows.
- **INOV**: identical to UNQ but the reference is the **equal-weight average of the 10 frozen core features** (a feature equal to −1/NaN is dropped from that row's average; row with all 10 missing drops out). Zero rule applies likewise. Null only if NONE of the core features are present.
- Reference for UNQ: `explain_scoring` says "the fixed benchmark model"; the live board has a `Benchmark` row (unq = 0 by construction); the published benchmark column is `v1_sherpa` (train/validation/live files) and at predict-time it is handed to you as a Series named `eiq_minera_model`. The hosted-train tool text alternatively calls real UNQ "stake-weighted leave-one-out crowd consensus at round close" — treat this as an ambiguity; everything downloadable points to v1_sherpa being the reference. Diagnostics-board UNQ is also "against the platform's own benchmark models".
- Horizon/timeline: round data date = exped day. Partial scores start the first trading session after the data date (round `score_at` ≈ T+3 calendar days), walk T+1..T+20, resolve at **23 trading sessions** (20-day horizon + 2-session lag + close day); `resolve_at` ≈ data date + 33 calendar days. Partial and resolved payout use the same formula at different horizons.
- Implications: (1) maximise cross-sectional rank correlation with a 20-day forward return bin; rank-normalising inside predict is free. (2) Total ≈ 3·FIT − β_b·FIT_bench − β_c·FIT_core on rounds where the references are positive, so raw FIT remains the dominant lever, while *de-correlating from the benchmark and from the core-feature average without losing FIT* adds up to ~2× extra credit. Live benchmark FIT is weak (0.009 mean over 36 rounds), so live UNQ ≈ FIT − small penalty (top live models show unq ≈ 0.5–0.6 × fit); on the validation board the benchmark is stronger and unq is only ~0.2–0.3 × fit. (3) Because of the zero rules, going *negative* on the benchmark direction is never rewarded extra; partial orthogonalisation is the right shape. (4) Round-level Sharpe matters for staking later; feature_exposure (max |spearman(pred, feature)|) is reported and top models sit at 0.55–0.72.

## 3. .pkl contract (upload_model / lane), verified from SDK docstrings + get_started
- ONE accepted shape: a **cloudpickled callable** `predict(live_features)` or `predict(live_features, live_benchmark_models)`. Input: DataFrame of `feature_*` columns indexed by instrument id (select columns BY NAME; served frame may carry extra cols). ## 4. Auto-run lane and the manual daily flow
- `lane_enabled: true`, `lane_active: true` on this deployment. The lane fires "shortly after each round opens" (rounds open 13:01:50–13:02:18 UTC in the log) and writes a real submission; `status` cycles submitted/running/skipped/error each round. A direct `submit_futures_predictions` for the same (model, exped) replaces the lane's entry; the lane never overwrites a direct one (409).
- Manual flow (SDK, works on Windows/Linux; pure-Python httpx):
  1. `rnd = client.get_current_round("futures")` → require `submission_window == "open"`, read literal `exped` (never "current").
  2. `live = pd.read_parquet(client.download_dataset(universe="futures", split="live"))` (→ GET /api/v1/futures/data/live); optionally `client.download_benchmark(universe="futures", split="live")`.
  3. predict, rank-pct within the exped, `preds = {id: float}` covering **exactly** the 90 ids (no extras/dupes/NaN), values in [0,1].
  4. `client.validate_submission(preds, exped=rnd["exped"])` (POST /api/v1/futures/predictions/validate; free, no write) → fix `issues`.
  5. `client.submit_futures_predictions(MODEL_ID, preds, exped=rnd["exped"])` (POST /api/v1/futures/submit/v2, JSON `{model_id, exped, predictions:[{instrument_id, prediction}]}`) → 201, read `replaced`, `late`, `scored`.
  6. `client.get_submission_status(tournament="futures", round=exped, model_id=MODEL_ID)` (GET /api/v1/submissions) to confirm coverage_pct = 100.
- Clock: Mon–Fri, open 13:00 UTC (actual 13:02), close 16:00 UTC; weekends dark; next window **2026-11-16 13:00–16:00 UTC**. Submissions when no window is open are accepted but `late: true, scored: false`. Resubmission while open replaces; after close 409. Round numbering: round 37 = exped_8055 (2026-11-13).

## 9. Modelling levers implied by the contract
- Per-exped rank-based covariance ⇒ train on cross-sectionally ranked/centred targets, evaluate per exped, embargo ≥20 expeds (the SDK starter uses tail-100 holdout with 20 embargo; the hosted trainer uses 4-fold exped-purged CV with embargo 20, min gap 21).
- Multi-target: 14 auxiliary targets with 0.19–0.84 correlation to everest → train per-target models and blend (classic Numerai gain); Tougroute (0.84) is likely a near-horizon sibling.
- UNQ/INOV: use `predict(live_features, live_benchmark_models)` to partially orthogonalise against the benchmark ranks at inference (tune the shrink factor on validation diagnostics); approximate core-feature neutralisation offline with the strongest univariate features / hosted-job INOV probes, then confirm on the diagnostics lane. Residualise-to-benchmark training is available both locally (train benchmark file, but in-sample-inflated) and hosted.
- Missing values: −1 should be NaN/categorical in our own trainer (LightGBM native missing), not an ordinal; the deployed baseline treats it as 0/ordinal.
- Daily ops: upload the final cloudpickled ensemble (built under 3.11 or 3.12 against the pinned libs) and let the lane submit; keep the SDK manual path as the fallback and as a pre-close checker (`get_submission_status`). Rank-pct inside predict so [0,1] is guaranteed.
